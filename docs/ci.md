# Prepared CI and attribution

The workflow at [.github/workflows/ci.yml](../.github/workflows/ci.yml) is prepared for `push`, `pull_request`, and manual dispatch after authorized publication. No repository has been pushed and no hosted run is claimed. It uses ordinary hosted Windows 2022/Ubuntu 22.04 jobs, without paid model services, dependencies to install, account integrations, or purchased infrastructure. Hosting remains subject to the repository owner's GitHub availability/usage rules; this local phase incurred no CI run.

There are two matrix jobs at most, `max-parallel: 2`, with a ten-minute per-job limit and cancellation of superseded runs on the same ref. Only `contents: read` is granted. Checkout does not persist credentials and fetches one commit. No secrets input, token forwarding to application code, artifact publishing, deployment, elevated pull-request trigger, or write-back step is present. Read-only permissions describe the repository token; the checkout filesystem is writable so tests can create scratch artifacts.

Each job selects exact CPython 3.11.9/x64 with `check-latest: false`, prints its version, runs the meaningful standard-library unit suite, and runs the [asserting offline demo checker](demos.md). `PYTHONUTF8=1` provides consistent text decoding. The runtime setup may fetch a Python distribution on the hosted runner; no distribution has been downloaded/installed on the local HP for this package. No `pip` or container step is included.
